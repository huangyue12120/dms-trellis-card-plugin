# v1.2 Integration Candidate

This is an unreleased integration draft, recorded 2026-10-08. The manifest is
still `1.0.0`; no matching v1.2 tag, prerelease, or stable release exists. Minimum
supported DMS remains `1.6.2`, with the same settings/process permissions.

## Changes

- Recent Trellis Changes keeps up to 200 runtime semantic observations with
  Snapshot provenance, quiet initial/reload baselines, and reliable failure
  recovery. It does not infer completion/deletion from missing tasks, persist
  history, or add watchers.
- Popout search matches project name, task title, and task ID in Live, Archive,
  and All. Archive metadata reads are bounded and cancellable, with explicit
  partial coverage and continuation. Empty queries schedule no archive I/O.
  Detail Back retains bounded search context and offers Retry after cancellation.
- Project and live/archive task Actions copy verified identities/canonical paths
  and open trusted folders. Fresh authority and containment are checked before
  execution. Clipboard arguments use `dms cl copy -- VALUE`; folder URLs encode
  path segments. Feedback distinguishes copied data, accepted launch, and local
  failure. Terminal/editor integration is deferred.
- Existing detail reads now check current configured-root authority so retained
  project metadata cannot authorize reads after root removal.

These changes retain the read-only parser/Snapshot boundary, existing Health,
Diagnostics, Desktop and Launcher surfaces, and shared watcher ownership. They
add no Trellis mutation, network access, permission, or independent database.

## Verification and remaining gates

Fixture/static reviews exercise actual daemon/widget JavaScript with host
transport mocked. This evidence is separate from native rendering, real
clipboard/folder behavior, and lifecycle observations on DMS. The integration
evidence and remaining host checklist live in
[the acceptance task](../../.trellis/tasks/archive/2026-10/10-08-v12-acceptance-release/acceptance-evidence.md).

Required host gates include keyboard/focus and narrow layouts, search/history
interaction, real clipboard and folder targets, multi-widget/Desktop behavior,
settings/manual/automatic refresh, locale, reload/disable/enable, and restart.
The known DMS State writer error leaves restart preference persistence
unestablished. It is host-owned code; no alternate persistence store was added.

`qmllint`/`qmlformat` are unavailable. The isolated offscreen harness could not
load the unchanged baseline's DMS imports, so it provides no component pass.
Host loading and individual runtime results must be recorded independently.

The first live v1.2 hot reload failed at the new `lib/trellischanges.js` import
with Qt's `File name case mismatch`, despite verified exact-case disk/import
names and installed bytes. The original 13-file plugin was restored and its
reload succeeded. A fresh isolated Qt engine imports and executes the exact
new library, but this probe alone did not load the complete DMS candidate.
A later manual reload succeeds: host logs at 17:21:10 confirm widget/daemon
loading; current IPC reports `loaded`; all 14 installed files match the checked
candidate. The user reported "验收了，看着没什么问题" and requested archival.
This is overall user-reported acceptance, not independent verification of every
host scenario. The initial failure's cause and restart persistence remain
unconfirmed. The five v1.2 tasks are archived at the user's explicit request;
this does not publish v1.2.0 or waive the remaining release gates.

## Packaging and rollback

The local review ZIP contains only `TrellisDms/`, `README.md`, and `LICENSE`,
excluding tasks, journals, private evidence, and repository metadata. It is
labeled an unreleased integration artifact and retains manifest `1.0.0`.

Back up the installed plugin before replacement. To roll back, restore that
directory and reload the plugin; Trellis project files are unchanged.

Stable v1.2.0 remains conditional on the required acceptance matrix, a matching
manifest/package, source ancestry/tag validation, and publication evidence.
The existing generic candidate workflow creates prereleases only. A v1.2 tag
must not be created while the manifest remains `1.0.0`.
