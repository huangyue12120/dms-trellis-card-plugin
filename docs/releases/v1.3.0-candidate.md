# v1.3.0 Notifications Candidate

This is an unreleased v1.3 integration candidate recorded 2026-10-09. The
manifest remains `1.0.0`; no v1.3 tag, prerelease, registry submission, or
stable release has been created. Minimum supported DMS remains `1.6.2`.

## Implemented

- Added an explicitly opt-in `notificationsEnabled` setting, defaulting to
  `false` and restored to `false` by Restore Defaults.
- Added bounded, runtime-only Health transition state. Initial/restart
  observations are quiet; a project/root emits at most one degraded and one
  corresponding recovered notification, with duplicate/cooldown suppression.
- Added localized, bounded, privacy-safe text and an argv-only local
  `dms notify` adapter. Notification text and argv never carry paths, IDs,
  task/session content, Markdown, or inferred Agent activity.
- Notification process failures, disable teardown, root-scope changes, and
  daemon destruction remain outside Snapshot warnings and scan ownership.

## Deferred gates

- **Task Change notifications — `DEFER`.** Recent Trellis Changes already
  provides passive semantic observations; this repository has no usage
  evidence that archive/new-active alerts justify interruption or maintenance
  cost. See the [archived v1.3.2 gate record](../../.trellis/tasks/archive/2026-10/10-09-v132-task-change-gate/gate-decision.md).
- **Control Center — `DEFER`.** Desktop Health, Popout, Recent Changes,
  Diagnostics, and Launcher already cover the proposed workflows. No new QML,
  manifest component, projection, scanner, or watcher is justified. See the
  [archived v1.3.3 gate record](../../.trellis/tasks/archive/2026-10/10-09-v133-control-center-gate/gate-decision.md).

## Verification and remaining gates

The pure transition fixtures, full Node contract suite, static argv/settings
checks, JSON parsing, task validation, and scoped diff checks pass. The helper
source retains QML's `.pragma library`; direct Node syntax checks require a
temporary pragma-stripped copy, as with the existing QML helpers.

No supported DMS 1.6.2 runtime session was available for this candidate. Popup
delivery, enabled/disabled behavior on host, degraded/recovered transitions,
restart quietness, duplicate suppression, and non-zero process failure
isolation remain **UNVERIFIED**. Local DMS CLI/API inspection establishes the
argv shape only and does not waive the host gate.

The manifest permissions remain `settings_read`, `settings_write`, and
`process`; no network or Trellis write capability was added. Do not bump the
manifest or publish a stable v1.3.0 until the supported-host and existing
release gates are complete.
